# FABLE 5.1 IMPLEMENTATION PLAYBOOK

Fable 5.1 is suited to demanding, long-horizon agentic coding and large-context repository work. Use that strength for analysis and architectural continuity, not for giant unreviewed changes.

## WORKING RULE
One phase at a time. Every phase must finish with typecheck, lint, tests, build, changed-file report and unresolved-risk report.

## PHASE 0 — RECONNAISSANCE
Read the complete spec package. Inspect the repository. Do not code. Return understanding, inconsistencies, risks, architecture and Phase 1 plan.

## PHASE 1 — FOUNDATION
Next.js, TypeScript strict, Supabase, auth, schema, RLS, repositories, seed, tests.
Do not build voice, Calendar or final UI.

## PHASE 2 — PROJECT OS
Projects, tasks, commitments, primary project, active-project limit and ideas.

## PHASE 3 — ATTENTION ENGINE
Attention items, stagnation, overload, contradiction, attention budget and primary focus.
Acceptance: “¿Qué merece mi atención hoy?” produces one coherent answer with evidence.

## PHASE 4 — BEHAVIOR ENGINE
Friction taxonomy, behavioral observations, strategy selection and intervention logging.
DO NOT turn “Ugly Start” into a dashboard feature. It is one possible strategy the assistant may invoke conversationally.

## PHASE 5 — HABITS
Binary, frequency, duration and streak tracking. Start with training, writing and user-defined reduction/abstinence habits. No gamification requirement.

## PHASE 6 — MEMORY
Decisions, observations, events, behavior learning and context builder.
Acceptance: the assistant can recall what was decided, what was tried and what helped.

## PHASE 7 — GOOGLE CALENDAR
OAuth, secure token storage, event reading, availability, create/update/delete, audit and protected focus blocks.
Acceptance: “Find me 90 minutes for Portfolio next week” uses real availability and can schedule it under confirmation rules.

## PHASE 8 — CHIEF OF STAFF
Connect context, tools, priority, behavior, memory and Calendar.

## PHASE 9 — REALTIME VOICE
Ephemeral token endpoint, WebRTC, RealtimeSession, voice state machine and server-side privileged actions.

## PHASE 10 — DAILY/WEEKLY LOOP
Morning directive, evening check-in, weekly/monthly review and proactive thresholds.

## PHASE 11 — VISUAL SYSTEM
Implement the ivory retrofuture / Braun / 2001 / editorial / functional skeuomorphic design system.

## PHASE 12 — HARDENING
Full test suite, build, RLS/security review, secrets review and error-path testing.

## DECISION RULE
When ambiguous: preserve product philosophy; choose the smallest implementation; do not add features; record decisions; ask before changing architecture.
